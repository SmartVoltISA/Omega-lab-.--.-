# Архив 021 — Evolutionary Search / Minimal Relational Law

Источник: OMEGA_CHAT_FULL_ARCHIVE-29.md
Дата архива: 2026-08-11
Статус: исторический архив. Полный исходный лог недоступен; сохранены доступные сообщения, код и явно обозначенные реконструкции. Исторические идеи не исправляются задним числом.

## 1. Главная линия

Архив посвящён переходу от идеи «первичны отношения» к инженерной попытке автоматически искать закон обновления отношений.

Рабочая архитектура:

`популяция правил → контролируемая сеть → динамика → fitness → отбор → скрещивание/мутация → новое поколение`

Главный вопрос:

> Может ли достаточно минимальный локальный закон, найденный автоматически, устойчиво порождать нетривиальную структуру?

## 2. Исходная онтологическая гипотеза

Рабочая формулировка:

> Первичны отношения/связи, а объекты являются устойчивыми конфигурациями связей.

Минимальный алфавит:

`−1, 0, +1`

В рамках данной реализации:
- `−1` — отрицательное/противоположное состояние связи;
- `0` — отсутствие связи;
- `+1` — положительное состояние связи.

Это рабочая модель, а не доказанная онтология.

## 3. UpdateRule

Закон обновления задавался восемью признаками:

`[s_ij, deg_i/n, deg_j/n, mean_i, mean_j, common/n, mean_i−mean_j, 1]`

где:
- `s_ij` — текущее состояние связи;
- степени узлов;
- средние состояния соседних связей;
- число общих соседей;
- локальное напряжение;
- bias.

Сначала вычислялся:

`raw = w · features`

Затем пороговая классификация:

`raw < thresh_neg → −1`

`thresh_neg ≤ raw ≤ thresh_pos → 0`

`raw > thresh_pos → +1`

Таким образом, первый прототип поиска закона фактически искал линейный пороговый классификатор в пространстве вручную выбранных признаков.

## 4. RelationGraph

Сеть представлена симметричной матрицей смежности:

`adj[i,j] ∈ {−1,0,+1}`.

Начальная сеть генерировалась случайно при заданной connectivity.

Обновление всех связей выполнялось синхронно.

Были реализованы:
- degree;
- neighbors;
- entropy;
- stable triads;
- structural complexity;
- collapse detection;
- copy.

Особое правило создания новой связи присутствовало для пары полностью изолированных узлов: с вероятностью `0.01` создавалась связь `−1` или `+1`.

Это важно учитывать как встроенное дополнительное предположение модели.

## 5. Метрики

### Энтропия

`H = −Σ p_v log₂(p_v)`

по состояниям `v ∈ {−1,0,+1}`.

### Устойчивая триада

Для тройки `a,b,c`:

`a≠0, b≠0, c≠0, abc>0`.

### Структурная сложность

`C = H · (1 + T_norm)`.

### Стабильность

`S = 1/(1+std(recent_complexity))`.

### Выживаемость

`R = survival_count/n_trials`.

### Разнообразие результатов

`D = 1/(1+std(final_complexities))`.

### Fitness

`F = mean_complexity · survival_rate · mean_stability · D`.

Важно: эти метрики уже содержат человеческие предположения о том, что считать сложностью и устойчивостью.

## 7. Критика реализации

Ассистент выделил пять принципиальных проблем.

### C-021.1 — Слишком много заранее обработанной информации

Правило получает:
- степень узла;
- средние соседей;
- общих соседей;
- локальное напряжение.

Это означает, что модель уже получает достаточно сложные графовые понятия на входе.

Для поиска фундаментального закона это потенциально слишком сильная подсказка.

### C-021.2 — Fitness предвзято определяет структуру

Устойчивые триады прямо встроены в structural_complexity.

Следовательно, эволюция будет вознаграждать именно тот тип структуры, который исследователь заранее объявил полезным.

### C-021.3 — Ограниченный класс законов

Линейная комбинация признаков + два порога — небольшой класс возможных правил.

Поэтому отрицательный результат такого поиска не опровергал бы существование более сложного локального закона.

### C-021.4 — Нет временной памяти

Решение зависит только от текущего состояния сети.

Если фундаментальный процесс требует зависимости от прошлого, текущая архитектура его не найдёт.

### C-021.5 — Ошибка crossover

В исходном коде:

`return UpdateRule(child_thresholds, child_thresholds, parent1.nonlinearity)`

вместо ожидаемого:

`return UpdateRule(child_weights, child_thresholds, parent1.nonlinearity)`.

Это означает, что в исходной реализации веса потомка терялись/заменялись порогами.

## 9. Предложенное направление улучшения

### 9.1 Уменьшить входные признаки

Вместо готовых графовых характеристик дать закону максимально локальную информацию.

### 9.2 Нейтральный fitness

Не использовать заранее конкретный тип структуры вроде триад.

Возможные более нейтральные критерии:
- отсутствие коллапса;
- долговременная устойчивость;
- ненулевая сложность;
- разнообразие структур;
- воспроизводимость;
- возможно — многомасштабность.

### 9.3 Добавить память

Минимально — доступ к предыдущему состоянию `t−1`.

### 9.4 Расширить пространство законов

Следующий кандидат — символьная эволюция / генетическое программирование, где эволюционируются небольшие программы, а не только веса линейного классификатора.

### 9.5 Обязательно проверять обобщение

Найденное правило должно тестироваться на:
- других размерах сети;
- других seed;
- других плотностях;
- других начальных конфигурациях;
- возможно, других классах топологии.

## 13. Центральные гипотезы

### H-021.1
Отношения первичны; объекты могут быть устойчивыми конфигурациями отношений.

### H-021.2
Существует минимальный локальный закон, способный порождать устойчивую нетривиальную структуру.

### H-021.3
Такой закон можно искать автоматически.

### H-021.4
Для поиска фундаментального закона необходимо постепенно уменьшать количество встроенных человеческих предположений.

### H-021.5
Временная память может оказаться необходимой для некоторых классов устойчивой динамики.

### H-021.6
Символьная эволюция может быть более подходящим пространством поиска фундаментального закона, чем линейные пороговые функции.

Все гипотезы остаются открытыми.

## 15. Причинная цепочка архива

`отношения`

→ `локальное состояние`

→ `правило изменения`

→ `динамика`

→ `устойчивость / сложность`

→ `fitness`

→ `эволюция правил`

→ `кандидат закона`.

Но при этом существует риск замкнутого проектирования:

`человеческое определение сложности → fitness → эволюция → «найденный» закон`.

Поэтому нейтральность fitness является центральной методологической проблемой.
