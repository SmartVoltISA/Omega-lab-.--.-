# Ω-LAB — ИСТОРИЯ ЧАТОВ

Исторические архивы проекта хранятся последовательно. Каждый архив является отдельным источником и не переписывается задним числом.

## Нумерация и смысловые имена

| Архив | Короткое имя | Направление | Назначение |
|---|---|---|---|
| 001 | `MINIMAL-ONTOLOGY` | Минимальная онтология / Omega Sim | Различение, память, продуктивность, индивидуация, сравнительная онтология, Omega Lab, MVP и методология |
| 002 | `SPACE-ORGANS-SKILLS` | SPACE / органы / навыки | Среда ИИ, Self Model, функциональные органы, capabilities, Guardian, RF sensing, графовая память, восстановление навыков |
| 003 | `VIDEO-STRUCTURE-MEMORY` | Видео / структура / процесс / память | Визуализация, структура, каркас, объект, процесс, состояние, память и развитие визуальных экспериментов |
| 004 | `ARCHIVE-CORE` | Архивная архитектура | Правила полного архивирования, разделение источника и извлечения, причинно-следственные связи, узлы, рёбра и граф истории |
| 005 | `MEMORY-CAUSALITY-COMPETITION` | Память / причинность / конкуренция / критическая связность | Ω-0, Ω-MEM-1, Omega Breath, Ω-B, Ω-C, эксперименты с коллапсом, циклами, аттракторами и связностью |

## Правило хранения

Архив = исторический источник.

Он сохраняется независимо от последующего анализа. Повторы не удаляются автоматически.

После накопления архивов выполняется отдельный слой анализа:

`АРХИВ → ИЗВЛЕЧЕНИЕ → СРАВНЕНИЕ → НОВОЕ / ПОВТОР / РАЗВИТИЕ / ИЗМЕНЕНИЕ / ПРОТИВОРЕЧИЕ → УЗЛЫ → СВЯЗИ → РЁБРА → ГРАФ → КАНОНИЧЕСКОЕ ЗНАНИЕ`

## Цветовые статусы

- 🟢 `NEW` — новая информация
- 🔵 `REPEAT` — повтор
- 🟡 `DEVELOPMENT` — развитие
- 🟠 `CHANGE` — изменение
- 🔴 `CONFLICT` — противоречие
- 🟣 `TESTED` — проверено
- ⚪ `OPEN` — открыто / незавершено
- ⚫ `UNTESTED` — не проверено

## Важное правило

Если новый архив повторяет старый, старый архив не удаляется. Новый архив остаётся историческим источником, а в аналитическом слое фиксируется характер пересечения.

Если новый архив добавляет детали — детали объединяются с каноническим знанием, но источник сохраняется.

Если архивы противоречат друг другу — обе версии сохраняются до отдельной проверки.

## Имена файлов

Для исторических файлов используются короткие смысловые имена вместо безличного `OMEGA_CHAT_FULL_ARCHIVE`.

Пример:

`001-MINIMAL-ONTOLOGY.md`

`002-SPACE-ORGANS-SKILLS.md`

`003-VIDEO-STRUCTURE-MEMORY.md`

`004-ARCHIVE-CORE.md`

`005-MEMORY-CAUSALITY-COMPETITION.md`

Так директор проекта сразу видит не только номер, но и направление конкретного архива.
