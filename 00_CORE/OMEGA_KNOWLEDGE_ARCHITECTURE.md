# Ω-LAB — КАНОНИЧЕСКАЯ ОСНОВА РАБОТЫ СО ЗНАНИЕМ

**Status:** CORE / WORKING ARCHITECTURE
**Version:** v0.1

## 1. Назначение

Ω-Lab рассматривает любой исследовательский материал не только как набор фактов и текста, но как **структуру связей** между сущностями, идеями, состояниями, операциями, экспериментами и выводами.

Это правило применяется универсально: к отдельному сообщению, чату, серии чатов, эксперименту, математической конструкции, технической системе и всей истории Ω-Lab.

## 2. Основная единица

Любой материал может быть разложен на:

**УЗЛЫ** — сущности, идеи, определения, вопросы, гипотезы, операции, эксперименты, результаты, выводы, ошибки, решения и состояния.

**СВЯЗИ** — отношения между узлами.

**РЁБРА** — конкретные направленные или ненаправленные экземпляры связей.

**ГРАФ** — совокупность узлов и рёбер.

**ПУТЬ** — последовательность связанных переходов.

**ВЕТВЬ** — отдельное направление развития.

**СТРУКТУРА** — организованная совокупность взаимосвязанных элементов.

## 3. Связь важнее простого соседства

Сам факт, что два понятия находятся рядом в тексте, ещё не означает наличие связи.

Связь должна быть определена по смыслу, контексту или явно выраженному отношению.

Примеры:

- A → причина → B
- A → следствие → B
- A → уточнение → B
- A → развитие → B
- A → изменение → B
- A → зависит от → B
- A → проверяется → B
- A → получено из → B
- A → противоречит → B
- A → повторяет → B
- A → является частью → B
- A → порождает → B

## 4. Причинно-следственная цепочка

Особое значение имеют переходы:

**вопрос → гипотеза → аргумент → эксперимент → результат → наблюдение → вывод → новая гипотеза**

Эта последовательность должна сохраняться при архивировании и анализе, потому что она показывает не только *что* было известно, но и *как* возникло следующее знание.

## 5. Временная структура

Любая идея имеет историю.

Если идея изменилась, сохраняются все версии:

**версия A → критика/новые данные → версия B → эксперимент → версия C**

Старая версия не удаляется только потому, что появилась новая.

История изменения является частью знания.

## 6. Разложение и сборка

Одна и та же система может рассматриваться на разных масштабах:

**целое → части → узлы → связи → рёбра → графы → подграфы → более крупная структура**

И наоборот:

**элементы → связи → узел более высокого уровня → структура → целая система**

Поэтому «целое» на одном уровне может выступать «узлом» на следующем уровне.

Это позволяет применять один и тот же принцип к математике, экспериментам, программному коду, разговорам, физическим моделям и архитектуре Ω-Lab.

## 7. Архивирование чатов

Для исторических чатов сохраняются два разных слоя:

### SOURCE
Максимально доступный исходный материал.

### EXTRACTION
Извлечённые из него сущности, тезисы, определения, гипотезы, эксперименты, результаты и связи.

Источник и интерпретация не должны смешиваться.

## 8. Статусы элементов

Используется рабочая цветовая маркировка:

- 🟢 **NEW** — новая информация;
- 🔵 **REPEAT** — повтор уже существующей идеи;
- 🟡 **DEVELOPMENT** — развитие существующей идеи;
- 🟠 **CHANGE** — изменение предыдущей позиции;
- 🔴 **CONFLICT** — противоречие;
- 🟣 **TESTED** — реально проверено;
- ⚪ **OPEN** — открыто/незавершено;
- ⚫ **UNTESTED** — не проверено.

Цветовой статус не удаляет источник и не заменяет историю.

## 9. Дублирование

Повтор не удаляется автоматически.

Различаются:

**полный дубликат** — смысл не добавляет нового;

**повтор с уточнением** — добавляет детали;

**повтор с развитием** — меняет или расширяет идею;

**повтор с новым экспериментом** — добавляет проверку;

**противоречивый повтор** — требует отдельного анализа.

Только после проверки можно считать элементы избыточными на уровне канонической структуры. Исторический источник при этом сохраняется.

## 10. Определение текущего состояния

Для каждого направления необходимо иметь возможность ответить:

- что придумано;
- что сформулировано;
- что доказано;
- что наблюдалось;
- что проверено экспериментом;
- что не проверено;
- что опровергнуто;
- что изменено;
- что завершено;
- что остановлено;
- что осталось открытым;
- откуда произошло направление;
- куда оно привело.

## 11. Роль знаний модели

Общие знания модели, логический вывод и внешний материал могут использоваться для анализа и построения структуры **только как отдельный слой**.

Они не должны незаметно заменять содержание исторического источника.

Разделение:

**SOURCE → извлечённое знание → MODEL INFERENCE / EXTERNAL KNOWLEDGE → проверенный вывод**.

Если источник не поддерживает утверждение, это должно быть явно отмечено.

## 12. Универсальность

Этот принцип не ограничивается чатами.

Один и тот же подход может применяться к:

- математике;
- физике;
- программному коду;
- экспериментам;
- техническим системам;
- архитектуре;
- базам данных;
- документации;
- истории проекта;
- гипотезам;
- моделям;
- знаниям;
- любым сложным системам.

## 13. Главный принцип

> **Не хранить только элементы. Хранить элементы вместе с отношениями, историей их возникновения и переходами между состояниями.**

Именно связи позволяют из набора отдельных знаний восстановить систему.

## 14. Рабочая формула

**ИСТОЧНИК → УЗЛЫ → СВЯЗИ → РЁБРА → ГРАФ → ПУТИ → СТРУКТУРА → СОСТОЯНИЕ ЗНАНИЯ**

И обратный путь:

**СТРУКТУРА → ПОДСИСТЕМА → УЗЛЫ → СВЯЗИ → ЭЛЕМЕНТЫ → ИСТОЧНИКИ**

Это является рабочей основой построения и восстановления Ω-Lab.
