# Ω-Lab — FOUNDATION ENTRY PROTOCOL v1.1

**Status:** CORE / READ FIRST

This is the entry rule for every new chat, agent, organ, experiment and continuation.

## 1. First read the foundation

Before planning, coding, experimenting or interpreting:

**FOUNDATION → PLAN → WORK/HISTORY → ARCHIVE**

No later layer may override the foundation without an explicit foundational revision.

## 2. Foundation is fixed on the stone

The foundation is the source of structural rules. It is not rewritten to fit a current task.

Core:

**MEMORY + BIDIRECTIONAL TRANSFORMATION**

**РАЗНОЕ → СВЯЗИ → ЦЕЛОЕ → FEEDBACK → РАЗНОЕ**

**ОПОРА → УЗЕЛ → СВЯЗЬ → РЕБРО → ГРАФ → ЦЕЛОЕ**

See `OMEGA_FOUNDATION_ARCHITECTURE_v1.1.md` and `OMEGA_MEMORY_INTEGRITY_PROTOCOL_v1.0.md`.

## 3. History is memory

History is not a separate storage concept. **History is the temporal form of memory.**

It must operate by the same principles as organism memory: preserve current usable state, preserve prior states and differences, preserve provenance, support retrieval by relevance and distance, and never silently destroy the path that produced the current state.

The history layers correspond to the memory layers:

```text
ACTIVE HISTORY
    ↓
current / near memory — what the next action needs now

PASSIVE HISTORY
    ↓
near-to-far retrievable memory — completed, paused,
rejected or inactive work that remains available by relation/context

ARCHIVE HISTORY
    ↓
far / durable memory — immutable historical evidence of what happened
```

The layers are not separate memories. They are different operational distances and states of the same historical memory.

## 4. History retrieval

History must be retrieved structurally, not merely chronologically.

When a new task begins:

```text
CURRENT CONTEXT
      ↓
ACTIVE HISTORY
      ↓
related PASSIVE HISTORY
      ↓
relevant ARCHIVE
      ↓
reconstruct sufficient context
      ↓
ACT
```

The system must not assume that the newest conversation contains the full state. It must retrieve the minimum sufficient historical context and expand outward when relations, contradictions, provenance or missing evidence require it.

Near history is used frequently. Far history is retrieved when relevant. Archive remains durable evidence even when it is not operationally active.

## 5. History movement

Historical material may move between layers as memory state changes:

```text
ACTIVE ↔ PASSIVE ↔ ARCHIVE
```

Movement is a state transition, indexing/retention change or retrieval-priority change — **never silent deletion**.

A previously archived item can become operationally relevant again without losing its archival identity. A current item can become passive without becoming forgotten. A passive item can be archived without losing provenance.

## 6. Historical record

Preserve:

**what was → what was done → what happened → what was verified → what changed → why → what follows**

For significant work, preserve where applicable:

- stable identifier;
- source;
- timestamp/cycle;
- predecessor/current state;
- action or experiment;
- result;
- verification;
- evidence and counter-evidence;
- relations to other work;
- reason for transition;
- derived state;
- next step.

Errors, failures, incomplete work, contradictions and frozen projects remain part of history.

## 7. Append, don't overwrite

History follows the memory integrity rule:

```text
S₀ → Δ₁ → S₁ → Δ₂ → S₂
```

A new state may supersede an operational state, but it must not silently erase the deltas, provenance or historical states that produced it.

Rework creates a new version:

```text
v1 → REWORK → v2
```

The old version remains recoverable.

## 8. Contradictions are memory

If historical records disagree:

```text
A says X
B says Y
      ↓
CONFLICT
      ↓
retain A + B + provenance
      ↓
resolve only with evidence
```

The resolution becomes a new state. The conflict remains historical evidence.

## 9. Freeze is memory state

A freeze is not destruction:

```text
ACTIVE → FROZEN
```

Frozen work remains retrievable and historically connected. Resumption creates a new continuation state.

## 10. Entry obligation

Any new participant must read the foundation before using the plan, active work or history.

The minimum entry order is:

**FOUNDATION → CURRENT STATE → PLAN → ACTIVE HISTORY → RELATED PASSIVE HISTORY → ARCHIVE WHEN NEEDED**

No agent, organ, experiment or chat may begin from an isolated local context when the task depends on prior system state.

**FOUNDATION FIRST. HISTORY ALWAYS.**
