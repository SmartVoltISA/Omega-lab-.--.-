# Ω-MEM — SELECTIVE ACTIVATION

## Статус

Архитектурный принцип / рабочая гипотеза. Требует последующей экспериментальной проверки.

## Основная идея

Системе не требуется постоянно держать всю накопленную память активной.

Следует разделять:

**активную память → рабочий граф → долговременное хранилище → архив**.

При возникновении задачи система определяет, какое знание, умение или состояние необходимо, извлекает соответствующий узел или минимально достаточный подграф, активирует его и после завершения задачи возвращает неиспользуемую часть в долговременное хранение.

## Принцип

> **Не максимальная активная память, а минимально достаточная активная память.**

Цель оптимизации — не минимизировать общий объём сохранённой информации, а минимизировать объём информации, который необходимо держать активным для текущей задачи.

## Аналогия с восстановлением навыка

Пример: езда на велосипеде.

Человеку не требуется каждый раз воспроизводить всю историю обучения: все падения, попытки и исправления. После обучения сохраняется относительно устойчивая структура навыка. При необходимости активируется релевантный набор связанных компонентов: баланс, управление, педалирование, координация и т. д.

Схематически:

`долговременное хранилище → поиск релевантного узла → активация подграфа → действие → результат → обновление навыка`

Забытое состояние не обязательно означает уничтожение информации. Оно может означать, что соответствующий граф или подграф находится вне текущего активного состояния и может быть повторно активирован при появлении подходящей задачи.

## Связь с предыдущими работами Ω-Lab

В исторических материалах уже зафиксирована цепочка:

**память → знание → опыт → практика → навык**

а также идея восстановления навыка через связанные узлы графа.

Этот документ формализует следующий шаг: **активировать не всю память, а только релевантный подграф**.

## Предполагаемый цикл

1. Поступает задача.
2. Определяется требуемая компетенция или знание.
3. По графу памяти находятся релевантные узлы.
4. Формируется минимально достаточный рабочий подграф.
5. Подграф активируется.
6. Выполняется действие / рассуждение.
7. Результат сравнивается с ожидаемым.
8. При необходимости структура навыка обновляется.
9. Неактивные элементы возвращаются в долговременное хранение.

## Потенциальное преимущество

Если механизм работает эффективно, он может снизить:

- объём оперативной памяти;
- число активных узлов;
- число вычислений при обращении к знаниям;
- время поиска релевантной информации;
- нагрузку на вычислительное оборудование.

Это **гипотеза**, а не установленный результат.

## Ограничение

Графовое хранение само по себе не гарантирует снижения вычислительной нагрузки. Полный обход большого графа может создать дополнительную стоимость.

Поэтому критическим элементом архитектуры является механизм **релевантности / адресации / извлечения минимально достаточного подграфа**.

## Будущий эксперимент

Сравнить как минимум две архитектуры:

### A — Full Active Context
В активном состоянии удерживается весь доступный контекст.

### B — Selective Activation
В активном состоянии находится только релевантный подграф.

Измерить:

- RAM / VRAM;
- время доступа;
- число вычислений;
- размер активного контекста;
- задержку ответа;
- качество выполнения задачи;
- стоимость восстановления навыка после периода неиспользования.

Особенно интересен сценарий:

**обучение → длительное отсутствие → задача → восстановление → повторная практика.**
