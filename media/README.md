# Видеопамять и визуальная философия Life-Network

## Базовый принцип

**Процесс — одна из основ Life-Network.**

Жизнь рассматривается не как набор застывших объектов, а как непрерывный процесс изменений. Процесс не обязан идти с постоянной скоростью: он может ускоряться, замедляться, менять характер и направление, но в модели он остаётся движением.

Застывший кадр — это не сам процесс, а **снимок состояния**, который становится памятью о процессе.

Поэтому базовая последовательность наблюдения:

`БЫЛО → ЕСТЬ → ИЗМЕНЕНИЕ → НОВОЕ ЕСТЬ → БУДЕТ`

Если имеется только один снимок, видно состояние. Если есть последовательность состояний, появляется история. Если известен механизм переходов между состояниями, появляется возможность анализировать направление изменения и осторожно оценивать следующее состояние.

## Структура не появляется — структура строится

Визуализация должна показывать **историю возникновения**, а не мгновенное превращение хаоса в готовый объект.

Правило LEGO-анимации:

`связь → узел → граф → устойчивый каркас → последовательное достраивание → структура → материал → форма → объект`

Каждый новый элемент присоединяется к уже существующей конструкции. Уже построенная часть не исчезает и не пересобирается заново без причины.

Каркас — это память предыдущих шагов, фундамент следующих шагов и ограничение для будущего развития.

## Два режима возникновения

### Целенаправленная сборка

Человек заранее знает желаемый результат и выбирает связи/элементы так, чтобы прийти к нему.

Примеры: LEGO, ручка, карандаш, электрический щит, механизм.

### Самоорганизация

Нет заранее заданной конечной формы. Возникают локальные взаимодействия, случайность, ограничения среды, усиление одних связей и исчезновение других. Устойчивые фрагменты сохраняются и становятся основой следующих структур.

Примеры для исследования: природные структуры, самоорганизующиеся системы, физические и космические процессы.

Это **режимы формирования**, а не утверждение, что все природные объекты имеют один и тот же механизм происхождения.

## Визуальное правило

Не показывать только результат. Показывать **как результат стал результатом**.

Карандаш или ручка — лишь демонстрационный объект. Тем же языком можно показывать любую историю формирования.

Главная фраза:

> **Не показывать результат. Показывать историю его возникновения.**

## Версионирование

Неудачные эксперименты не удалять. Каждая существенная попытка получает новую версию (`v01`, `v02`, `v03`...). Ошибки и исправления сохраняются как часть истории обучения.

## Работа с памятью проекта

Перед созданием новой визуализации, когда это существенно для задачи, сначала проверять существующие материалы Life-Network/Ω-Lab в GitHub: предыдущие ролики, описания, гипотезы, ошибки и принятые визуальные правила.

После эксперимента фиксировать:

1. что было задумано;
2. что получилось;
3. что не получилось;
4. почему версия считается неудачной/удачной;
5. что изменить в следующей версии.

GitHub используется как **внешняя память истории проекта**, а не как папка для очистки.

## Важное ограничение

Визуальная модель гипотезы не является автоматически доказательством физической теории. Сначала строится наглядная модель, затем она проверяется физическими данными, геометрией, экспериментом и/или расчётом.
