# Ω-REL-010 — Self-Generating Relation Space

Date: 2026-08-13
Status: PROTOCOL REGISTERED — EXECUTION REQUIRED

## Purpose

Determine whether the number of distinguishable relations can be generated by a minimal Ω dynamics without prescribing the cardinality of the relation space.

## Motivation

Ω-REL-009 established that choosing an internal state-space size N cannot reveal a fundamental relation count. Increasing N simply increases the available relative states/classes.

Therefore Ω-REL-010 removes N as a source of the answer.

## Minimal generative basis

Only the following operations are assumed:

`distinguish → interact → change → repeat`

No predetermined relation alphabet is used as the generator.

No predetermined maximum number of relation states is used.

## Operational definition of a relation

A candidate relation is an observable behavioral equivalence class generated by interaction.

Two candidate states are considered the same relation only if they are indistinguishable under the complete declared set of subsequent interventions up to the current search depth.

If two states produce different future responses under the same intervention, they remain distinct.

## Generative procedure

1. Start from the minimal distinguishable pair A and B.
2. Apply the smallest allowed interaction operation.
3. Record the resulting observable state.
4. Apply every allowed next interaction to every discovered state.
5. Canonicalize states under only explicitly justified symmetries.
6. Add genuinely new states/relations to the discovered set.
7. Repeat by generation depth.
8. Record the number of distinct relations at every depth.

Define:

`N_R(d) = number of distinguishable relation states/classes discovered by depth d.`

## Closure criterion

Finite closure is reached only when a complete generation produces no new distinguishable relation classes:

`N_R(d+1) = N_R(d)`

and the equality persists for the complete closure check, not merely for one sampled trajectory.

If new classes continue to appear with increasing depth, the system has not demonstrated finite closure.

## Unboundedness criterion

A finite maximum is rejected if, for every tested depth d, the generation procedure produces at least one new distinguishable relation and the result is not caused by an artificial state-space cap.

Finite computation cannot prove mathematical infinity; it can only provide evidence of unbounded growth within the tested regime.

## Forbidden shortcuts

Do not set:

- N = 8;
- N = 16;
- any other fixed relation cardinality;
- `{−,0,+}` as the generating alphabet;
- a manually specified list of relation types;
- an explicit relation variable R unless it emerges as a measured state rather than being inserted.

These may be used later as descriptive labels after the state space has been generated.

## Required controls

### Control A — no interaction

A and B remain independent. Record whether any relation classes are generated.

### Control B — one-way interaction

`A → B` only.

### Test C — mutual interaction

`A ↔ B`.

The comparison determines whether new relational classes are specifically generated by mutual interaction.

## Required output

The implementation must produce:

- exact state encoding;
- exact transition rules;
- generation depth;
- number of raw states per depth;
- number of canonical/distinguishable relation classes per depth;
- symmetry rules used for canonicalization;
- first appearance depth of every class;
- closure status;
- reproducible source code;
- complete result table.

## Core question

> Does the minimal Ω generator produce a finite closed relation space, and if so, what is its cardinality?

If finite closure occurs, the closure size is a candidate for the maximal relation count of that specific Ω generator.

If no closure occurs, the result is that this generator does not provide a finite maximum under the tested rules.
