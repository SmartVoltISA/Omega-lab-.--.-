# Ω — Relation Duality / Independent Weights

Date: 2026-08-13
Status: HYPOTHESIS / TO BE TESTED

## Observation

Different parts of one whole may participate in relations while retaining different internal parameters. The relation between two parts therefore need not be represented by a single symmetric scalar.

Working abstraction:

`A ↔ B`

with potentially distinct directional contributions:

`w(A→B)` and `w(B→A)`

and potentially distinct opposing components / counterweights.

This does NOT yet assert that every Ω relation is directed, asymmetric, or physical. It is a candidate structure to test.

## Connection to the existing Ω architecture

The relation-first architecture remains primary:

`relations → organization/intersections → structures → emergent nodes`

This document extends the relation layer; it does not introduce nodes as primitives.

## Candidate properties

A relation may potentially carry independent quantities such as:

- direction;
- magnitude / weight;
- counterweight / opposing contribution;
- resistance to change;
- persistence;
- capacity;
- energy cost of creation/change/destruction;
- history dependence.

These are candidate variables only. No variable is declared fundamental without testing.

## Core hypothesis H-REL-DUAL-001

A relation between two distinguishable parts may require at least two independently variable contributions (one associated with each direction/side) to reproduce the observed behavior of the system.

Alternative models must compete:

- M0: single symmetric relation value;
- M1: two directional relation values;
- M2: two directional values plus opposing/counterweight components;
- M3: history-dependent relation state.

## Minimal test

Use the smallest existing relation-based model that already produced stable structure. Do NOT introduce a new unrelated model unless the existing experiment cannot express the variable under test.

For each model:

1. reproduce the existing baseline result;
2. introduce the candidate relation property only;
3. keep all other rules fixed;
4. measure the same previously declared observables;
5. compare against the baseline;
6. remove the candidate property;
7. test whether the observed difference disappears;
8. repeat across independent seeds / runs as required by the existing protocol.

## Falsification criteria

The hypothesis is weakened or rejected within the tested model if:

- the symmetric relation reproduces all relevant observables;
- directional values collapse to an equivalent single value;
- the added counterweight parameter has no independent effect;
- the apparent effect disappears under controls or seed changes;
- the result is explained by an implementation artifact.

## Confirmation standard

Do NOT call the hypothesis confirmed merely because M1/M2 produces visually richer behavior.

A stronger result requires a reproducible observable that cannot be reproduced by the simpler competing model under the same protocol.

## Relation to whole / parts

The working Ω pattern is reversible:

`different parts → relations → organized whole`

and

`whole → decomposition → parts + relations`

This is an architectural hypothesis to be tested, not a physical law.

## Comparison with classical mathematics

Classical graph mathematics is a comparison and formalization tool. It is not used here as the starting ontology.

After an Ω result is obtained, compare it with standard graph/network formalisms:

- if the result is already fully represented, record that no new mathematical structure was identified;
- if only part is represented, isolate the unrepresented property;
- if not represented, define the new structure operationally and test it further.

## Required honesty rule

No result may be claimed until the actual code execution and checks are completed.

`Execution not verified. No experimental result claimed.`
