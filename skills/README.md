# Ω-Skills

Skills are the organism's learned, reusable procedures.

A Skill is not:

- a raw tool;
- a hardware organ;
- an LLM prompt alone;
- a memory entry;
- a single successful execution.

A Skill is a reproducible procedure built from memory, context, capabilities and tools, with feedback and verification.

## Skill anatomy

```text
TASK
 ↓
RELEVANT MEMORY / GRAPH
 ↓
CAPABILITIES
 ↓
TOOL SELECTION
 ↓
PROCEDURE
 ↓
EXECUTION
 ↓
RESULT
 ↓
VERIFICATION
 ↓
FEEDBACK
 ↓
MEMORY / GRAPH UPDATE
```

## A Skill should answer

- What problem does it solve?
- Under what conditions does it apply?
- What does it already know from memory/graph?
- Which capabilities are required?
- Which tools are used?
- In what order?
- What result is expected?
- How is the result verified?
- What has failed before?
- Where has it been used?
- What changed after feedback?
- Is it currently ready for execution?

## Lifecycle

`IDEA → CANDIDATE → SANDBOX → VERIFIED → ACTIVE → MONITORED → REFINED/RETIRED`

Failures are retained as experience and constraints. A stored Skill definition never implies current execution readiness.

## Boundary

Skills belong to the SPACE knowledge/learning layer. Concrete reusable instruments belong in the planned separate public Ω-Tools repository.
