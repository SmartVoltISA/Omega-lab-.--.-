# Ω-MEM-4 — AUDIT 2026-08-10

## Status

**Audit result: NOT YET VALIDATED.** The submitted Ω-MEM-4 run contains useful observations, but the implementation does not satisfy its own pre-registered protocol. The numerical output must therefore be treated as **exploratory evidence**, not confirmation of H-MEM-2.2/H-MEM-2.3.

The original submitted implementation is preserved as `omega_mem4_submitted.py`. No negative result is deleted.

## 1. Executive verdict

### 🟢 Strong / reusable observations

1. Periodic-4 shows a clean finite-state capacity threshold in the Counter architecture: S=1,2 ≈ 0.50 and S≥4 = 1.00.
2. Random-iid remains ≈0.50 across the tested families; the negative control behaves as expected.
3. The submitted Thue-Morse parity tracker does not solve the prediction task.
4. Simple context memory predicts the supplied Thue-Morse sequence substantially better than the submitted parity tracker.
5. The HMM experiment shows that the particular discretized belief implementation does not outperform last-observation context in the reported accuracy.

### 🟡 Interesting but not yet established

1. A general expressive-capacity threshold principle.
2. A minimal-sufficient-statistic principle.
3. A general relation between state information and prediction advantage.
4. The claim that random finite-state machines can beat structural designs after controlling for capacity.
5. A general causal interpretation of the permutation result.

### 🔴 Claims that must NOT be treated as established from this run

1. "Thue-Morse requires O(log n) memory." The experiment did not measure the minimum required representation.
2. "Matched architecture is beaten by Random S=64 after controlling for S." The submitted Matched P3 architecture is forcibly fixed at S=2, so this is not a same-S comparison.
3. "Context-2 is a true two-symbol context." The implementation stores only the previous symbol; Context-2 is effectively equivalent to Context-1.
4. "Markov-2 minimal sufficient statistic is confirmed." Because Context-2/Matched are implemented incorrectly, this conclusion is unsupported.
5. "Intervention produced +0.500 drop for Periodic-4." With reset_step=500 and a period-4 counter, state 0 is identical to the control phase at that point; the supplied intervention code should not yield the reported permanent +0.500 average drop. The reported intervention summary is inconsistent with the shown code/parameters.
6. "Permutation test proves causality." It tests whether the learned state→prediction mapping contains predictive information; it is not, by itself, a causal identification proof.

## 2. Protocol compliance audit

The pre-registered protocol in `PROTOCOL.md` requires: S through 128 where meaningful, unconditional entropy, reachable-state count, effective state entropy, memory lifetime/reconvergence, paired comparisons, 95% CIs, raw data, and strict intervention state/output divergence.

The submitted implementation actually provides only:

- accuracy;
- conditional entropy;
- a permutation control;
- an intervention function;
- 30 seeds;
- S through 64.

Missing or incomplete protocol requirements:

- S=128 is absent.
- unconditional H(next) is not computed.
- reachable-state counts are not computed.
- effective state entropy is not computed.
- memory lifetime/reconvergence is not computed.
- paired differences are not reported.
- 95% confidence intervals are not reported.
- all reachable reset states are not enumerated.
- state divergence is not reported separately from output divergence.
- full raw per-seed results are not archived by the submitted run.

Therefore the run is **protocol-incomplete**.

## 3. Critical code defects

### 3.1 Context-2 is not Context-2

Submitted implementation:

```python
self.next_state[(s,inp)] = ((s % 2) * 2 + code[inp]) % 4
```

This preserves only the previous input bit (`s % 2`) and appends the current bit. It therefore represents approximately one-step context, not the last two observations.

Consequence: the reported

`Context-1 = Context-2 = Context-3 = Matched = 0.834`

cannot be interpreted as evidence that Markov-2 needs no second-order context. Context-2 and the P2 Matched machine are structurally wrong for the stated test.

A correct k-context machine should retain the previous k observations, with state space 2^k (or an equivalent explicit encoding).

### 3.2 S sweep is silently ignored by several architectures

`Context-1`, `Context-2`, and `Context-3` overwrite `self.S` with 2, 4, and 8 regardless of the requested S.

P2 Matched overwrites S to 4.

P3 Matched overwrites S to 2.

P5 Matched overwrites S to 1.

Therefore rows such as P3 Matched S=2,4,8,16,32,64 are **not a sweep of expressive capacity**. They are repeated measurements of the same 2-state machine.

This directly invalidates the conclusion that increasing matched expressive capacity fails to rescue Thue-Morse: expressive capacity was not actually increased for that architecture.

### 3.3 P3 Matched is not a genuine structural match to the generator

Thue-Morse is generated as:

`t[n] = parity(popcount(n))`.

The submitted Matched machine instead updates a state using the parity of observed X symbols:

```python
(s + code[inp]) % 2
```

These are different quantities. The machine does not track the binary position n or the carry structure of n→n+1. Calling this architecture "matched" therefore overstates the structural correspondence.

Correct interpretation:

> The tested parity-of-observations architecture failed on Thue-Morse.

It is not yet a test of a correctly matched online Thue-Morse representation.

### 3.4 Random vs Matched comparison is unfair in P3

Reported:

- Random S=64 = 0.727
- Context-3 = 0.666
- Matched = 0.522

But Matched P3 is forcibly S=2. Random S=64 has vastly more state capacity.

Thus the statement `Random S=64 > Matched` is true numerically but does **not** isolate structural match from expressive capacity. The required same-S control was not performed.

### 3.5 Markov-2 report/table mismatch

The code uses:

```text
YY -> 0.1
YX -> 0.5
XY -> 0.5
XX -> 0.9
```

The supplied report text describes a different mapping in one place. The code should be treated as the executable definition, and the protocol/data record must use one canonical transition table.

### 3.6 Intervention result is inconsistent with the shown code

For P1 Periodic-4, reset_step=500 and S=4:

`500 mod 4 = 0`.

The control counter is therefore at state 0 immediately before the post-reset future is evaluated. Resetting to state 0 should initially produce the same state as control, not destroy the phase. The claimed +0.500 average accuracy drop is therefore incompatible with the displayed intervention implementation and parameters.

Additionally, the metric averages the whole post-reset interval, so a transient phase error would be diluted over hundreds of steps. A strict causal intervention must measure:

- immediate state divergence;
- immediate prediction divergence;
- recovery time;
- cumulative loss;
- all reset states, or a pre-registered representative subset.

### 3.7 Permutation is not causal identification

The permutation test shuffles prediction labels among learned states. A large original-vs-permuted gap establishes that the learned state labels carry predictive information under this evaluation. It does not establish that the memory state is a causal mediator in the stronger scientific sense.

Intervention is the relevant causal test, and the intervention implementation must first be corrected.

## 4. What Ω-MEM-4 actually establishes

### 🟢 Observation A — Periodic threshold

For the submitted Periodic-4 positive control:

- Counter S=1 ≈ 0.50
- Counter S=2 ≈ 0.50
- Counter S≥4 = 1.00

This is a clean demonstration that a cyclic representation with enough states can encode the period in this specific deterministic task.

It supports a **model-specific capacity threshold**, not a universal law of memory.

### 🟢 Observation B — Random-iid null

Across the tested architectures and state sizes, Random-iid remains ≈0.50.

This is a strong negative-control result for the submitted setup.

### 🟢 Observation C — Submitted Thue-Morse parity tracker fails

The tested parity-of-observed-X machine gives ≈0.522, close to baseline, while Context-2/3 give ≈0.666.

This establishes a failure of that particular parity tracker.

### 🟡 Observation D — Random finite-state machines improve with S

Random architectures improve substantially on structured deterministic data as S increases. This is important because it demonstrates that predictive performance can arise from accidental/implicit feature coding in a sufficiently large state machine.

But it does not yet show that random structure is intrinsically superior. A fair comparison requires matched S, multiple random ensembles, parameter-count/state-transition controls, and a correctly implemented matched architecture.

### 🟡 Observation E — HMM discretized belief representation

The submitted discretized Bayesian filter gives ≈0.70 accuracy and does not beat Context-1. This is useful evidence about the particular discretized implementation.

It does not show that Bayesian/matched memory is inferior in general.

## 5. Corrected scientific status

### H-MEM-2

🟡 PARTIALLY CONFIRMED.

Memory can carry predictive information in the tested architectures, but the general mechanism remains under investigation.

### H-MEM-2.1

🟡 REFINED.

The original universal formulation is too strong. Ω-MEM-3 demonstrated failure of the tested "matched" implementation on Thue-Morse, but Ω-MEM-4 shows that the implementation itself must be audited before attributing the failure to structural match.

### H-MEM-2.2

🟡 REFINED / OPEN TEST.

The idea that structural match must be combined with sufficient expressive capacity remains plausible, but Ω-MEM-4 as submitted does not provide a clean test because the P3 matched architecture is fixed at S=2 and is not truly position-matched.

### H-MEM-2.3

🔵 OPEN.

A useful candidate formulation is:

> Prediction advantage depends on whether the memory state is a sufficiently informative representation of the predictive state, subject to capacity and implementation constraints.

This is intentionally weaker than the submitted universal claim and is the correct target for Ω-MEM-5.

## 6. Required Ω-MEM-4 correction / replication

Do NOT erase the submitted run. Preserve it as an exploratory record.

Before accepting H-MEM-2.2 or H-MEM-2.3, rerun a corrected Ω-MEM-4R with:

1. Correct Context-k implementation.
2. True same-S comparisons.
3. Correct Thue-Morse online representations, including explicit position/carry representations and finite context baselines.
4. Matched P3 architecture whose capacity is actually swept.
5. Same parameter/state-count budget for Random vs Matched.
6. Multiple independent random FSMs per condition, not one random table per seed only.
7. Correct intervention with non-equivalent reset states and a pre-registered recovery metric.
8. Paired per-seed differences and 95% CIs.
9. Full raw per-seed JSON/CSV.
10. Unconditional entropy, conditional entropy, reachable states, effective state entropy and reconvergence time.
11. Explicit train/test separation and an independent test sequence where feasible.
12. No post-hoc claim that a particular complexity class (e.g. O(log n)) is required until measured.

Primary falsification question:

> When state capacity is held equal, does a correctly matched representation outperform an equally expressive but structurally mismatched representation on the same process?

Secondary question:

> Can an adaptive learner discover a predictive state representation without being told the process-specific structure?
